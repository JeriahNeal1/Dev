# Temporary RAM acquisition architecture

The owned object replaces both the inherited-RAM DUAL1.07 startup and ECUFlash's CRC/fill acquisition logic. It takes over execution for acquisition, then requires a real power/reset boundary. Host-native BF/A8 remains the supported way to observe untouched OEM state before this takeover.

The entry header contains two skipped NOPs. At fixed entry `FFFF3004`, the program sets private SP, SR.I15 and private VBR; disables and verifies DMA master operation and the on-chip watchdog; rejects ROM shadowing or nondefault MAT selection; initializes every private byte and both canaries; initializes its register state, SCI2 and the SCI2 pin function. There are no OEM subroutine calls, floating-point instructions, allocations, C runtime, writable code, or inherited RAM inputs. The complete byte map is `evidence/rk02/build/ARTIFACT_REVIEW_FINAL.json`.

The kernel owns 1,840 consecutive RAM bytes, of which 1,808 are uploaded and 32 are initialized after entry. The latter contain an 8-byte receive buffer, two 4-byte guards and a 16-byte exception stack. Normal execution uses zero stack bytes. One admitted hardware exception pushes 8 bytes before the private handler restores SP and enters a quiet terminal loop. Arbitrarily repeated NMI arrivals before that first handler instruction remain outside the bound. A pre-entry asynchronous event, corrupt upload, unknown external watchdog, or incorrect clock is an explicit physical/entry condition, not an assumed successful simulator default.

All 256 vector entries point to the same private failure handler. The large vector table is deliberate: unexpected exceptions have no inherited OEM handler to return through. No attempt is made to resume OEM code after its RAM may have been overwritten. The upload/session also has OEM-managed buffers and a loader stack; their independently recovered contracts are distinct from the new object's ownership map.

The packet is `BE EF | payload_length_BE16 | payload | sum8(all preceding bytes)`. Identity request payload `01` is accepted once and returns `81` followed by `A2WC511R-RK02` and NUL. A raw request is exactly `03 | pass_u8 | address_BE32 | 02 00`. Its response is `83 | pass_u8 | address_BE32 | 512 raw ROM bytes`. No request can set the internal next-read pointer: the decoded address must equal it. That pointer starts at zero, increases by 512, and resets only at 1MiB for the second pass. After two passes communication becomes quiet. The host rejects a wrong opcode, pass, address, length, identity or checksum.

The checksum detects some transport errors; it is never used to substitute a page. Two matching SHA256 hashes establish repeatability of received bytes, not immunity to every possible systematic electrical fault. Virtual lossless claims compare every returned byte directly with each complete known fixture. Physical transmission integrity remains a separate assumption.

The only kernel stores are private RAM initialization/receive/guards and documented DMAOR, WTCSR, SCI2 and PCCR operations. The final binary review enumerates all 22 store sites and proves their address domains. ROM, flash control stores, prohibited `FFFFE803`, arbitrary MMIO, executable targets outside the object and uninitialized RAM reads are rejected by the simulator's closed memory/execution model. A changed binary fails the checked builder's fixed-object review. These guards do not claim that an arbitrary new source program has been proved safe.

Receive waiting has no software timeout: a missing byte leaves polling reads and no new outputs. Host deadlines terminate a stalled operation; physical power loss terminates the kernel. Transmit-ready and final transmit-drain waits each have a 65,536-iteration budget. Every response starts by disabling receive, enabling transmit, and rejecting latched RDRF/error flags. Every response ends by waiting for TEND before restoring receive-only mode; normal completion then disables SCI2. TDR-buffered and TSR-shifting data are both modeled. Echoes whose start is ignored under RE0 do not become valid receives merely because RE becomes enabled before their completion. A new start after RX restoration is a different input and may terminate the protocol; no unbounded physical echo-delay tolerance is claimed. A failure disables SCI2 immediately; pending transmission may be discarded and the host must retain incomplete evidence. No failure causes a retry upload, arbitrary write, reset opcode, flash operation or synthesized successful acquisition.

The native uploader is the only supported upload interface. Its compiled data bind the exact kernel bytes/hash, ECU identity, upload address, entry, version, block size and two ascending passes. The Python protocol constructors are pure offline test/replay oracles with no transport capability. The fake provider's pre-kernel states are explicit OEM protocol models backed by stock instruction regressions. Kernel replies, in contrast, come only from actual compiled instruction execution through the SCI model.

The SCI model implements deterministic register and TDR/TSR events, including partial transport messages and error/failure paths. Its instruction ticks are not physical clock certification. RK02 has its own frozen eight-file runtime model, per-instruction fast/slow parity, full-image runs and fault/echo coverage. RK01 coverage is not carried into the RK02 totals. The exact final model identity is checked for every fixture and for each contributor to aggregate coverage.

Exit is transport close, verified ECU power loss/reset, restored ignition power, then a fresh passive OEM BF identity. An arbitrary key-off delay is not proof of power loss. The final human procedure must keep real adapter, electrical, external watchdog and reset behavior visibly conditional; no flash Write, Test Write, erase or program step belongs to this tool.
