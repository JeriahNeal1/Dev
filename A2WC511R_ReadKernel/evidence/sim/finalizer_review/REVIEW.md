# Finalizer and native transport review

The final reviewed finalizer is preserved at `input_03/finalize.py`, SHA256 `b55d0c85e6f3e6026a12c1360a77ad8bac892ed16891e69ddef4b18cfc1666ef`. Its read/parse path imports no DLL, socket, subprocess or hardware API. It writes only new local result files. No provider or physical transport was used in this review.

Two concrete findings were fixed:

- Non-message calls previously accepted impossible message metadata. The finalizer now requires the exact zero-count, empty-wire, zero-message-field shape generated by the pinned native host. The original source and six accepted negative cases are preserved; current code rejects them.
- Input files were originally re-read for their final hashes after validation. A synthetic race demonstrated a PASS result linking a later invalid 33-byte journal while replay had consumed an earlier 7 MiB journal. The finalizer now hashes the exact used buffers and rechecks inputs before publication. The fixed code rejects a change before publication; a later alteration cannot substitute its hash for the hash of bytes actually validated. Subsequent consumers must still verify recorded hashes.

`NATIVE04_REVIEW.json` independently replays the completed **actual** native04 composite capture. Both reconstructed 1 MiB passes equal the separately pinned composite fixture. Twelve altered real-journal controls reject wrong pass/address even with repaired checksums, invalid control metadata, an unsupported API/status, missing close and fake-to-physical flag mismatch. The native03-to-native04 source transition was independently confirmed identical outside `log_api`.

`FILE_RETEST.json` contains five separate synthetic file tests: partial raw image, wrong raw bytes, changed executable, an input change before publication, and the original later-hash race. `REPLAY_REVIEW.json` uses actual native03 wire bytes with explicitly fabricated test metadata only. Those synthetic captures are confined to `SYNTHETIC_*` directories and are not native04, physical, current-ROM or release evidence.

The raw finalizer proves capture integrity. It does not by itself prove a particular virtual fixture or physically associate an ECU; the independent native04 review and root validator separately check fixture identity. The finalizer explicitly leaves `physical_session_association_proven` and `current_ROM_identified` false. A physical build requires the bound certificate and distinct executable, and there was no physical build execution in this review.

The journal retains UTC/QPC and transport metadata. It does not record every argument to non-message calls, such as filter masks and IOCTL parameters; those are fixed by the reviewed pinned source/binary. It also does not reconstruct the exact host receive-deadline start or establish silicon timing. Close is not treated as an ECU reset.

Pre-fix source bytes remain under `input_01`; the control-shape intermediate version is retained under `input_02` with an exact SHA match to the earlier review report; the final source is under `input_03`. All earlier counterexamples remain intact.
