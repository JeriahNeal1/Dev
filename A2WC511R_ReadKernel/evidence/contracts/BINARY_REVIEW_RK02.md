# Independent RK02 final-object review

The 1,808-byte RK02 object, SHA256 `3a65d6f0700bae394a24ba9f552d03500b7f66e6344ec57613f10bfd360d8581`, passes the bounded independent binary/store/control review. This is software evidence for a temporary RAM acquisition tool; it is not physical approval or current-ROM attestation.

`review_binary_rk02.py` checks the actual big-endian ELF32 SH object, all 335 instruction words against the extracted binary, every direct control-flow target and PC-relative literal, the complete register-definition sets governing pointers, all 22 store sites, every vector and the loader checksum. The source has an exact full-image hash guard: it cannot silently approve another build. This is an explicit fixed-object semantic review with executable drift checks, not a general automatic theorem prover.

Four store sites touch private RAM: the eight-longword zero loop, two fixed guards and the length-guarded receive buffer. Their complete destination domain is `[FFFF3710,FFFF3730)`. The 16-byte private exception stack is `[FFFF371C,FFFF372C)`. There are no software stack pushes, computed calls, FPU instructions or external OEM calls. A single hardware exception uses eight bytes; the private handler resets SP and becomes quiet. Arbitrary repeated NMI arrivals before its first instruction remain outside the contract.

The other eighteen store sites address DMAOR, WDT, SCI2 and the documented PCCR mask only. No flash-controller or ROM stores exist. RAMER and FMATS are read-only admission guards. Every ROM load for acquisition comes from the fixed address counter: bases `0,512,...,0xFFE00`, exactly 512 bytes each, twice. Request bytes must equal the expected counter and cannot assign it. The only other data stream is the fifteen-byte immutable RK02 identity body. No inherited `FFFF5444` selector or OEM persistent buffer is read.

The self-echo correction is present in machine code. `FFFF3202` writes SCR20 before the first reply byte. `3204..3208` tests residual RDRF and receive-error bits with mask78; any set bit reaches terminal failure before a TDR write. `3270` calls the TEND drain after the final checksum byte. Only an observed TEND returns; expiry of 65,536 polling iterations reaches failure. SCR10 at `3278` restores receive-only mode after that return. No direct branch enters the restoration sequence. PR is saved in R14 across the two leaf helpers and restored before RTS.

Both the byte-ready and frame-drain polling loops have finite instruction budgets. RX idle or partial-frame polling remains deliberately unbounded and read-only. Host deadlines, stable clock, actual UART turnaround, DMA quiescence during upload, asynchronous entry events and verified power-loss exit remain separate conditions. Disabling RE can discard an incomplete incoming character; the host therefore sends only one fixed request at a time. The model must not promote byte-completion timing to measured silicon behavior.

`verify_upload_wire_rk02.py` then executes the actual stock loader, not a host decryption substitute: declaration34, fifteen encrypted36 blocks, and start31. Its 479,183 executed instructions make 452 ordered longword stores, reconstruct the exact RK02 bytes, emit the expected acknowledgements through executed TDR stores, verify sum5AA5 and reach `FFFF3004` with SP `FFFFBFA0` and SR.I15. The test retains its full compressed instruction/memory/MMIO trace. Seven negative controls reject invalid declarations, a bad start subcommand and a bad upload checksum. The bad36-packet-checksum control records the OEM's earlier RAM write and missing ACK rather than pretending failure is side-effect-free.

The OEM handoff report explicitly reuses the unchanged stock KWP/security, accepted-IRQ, quiescence and initial-boot evidence. Historical input hashes are resolved to exact retained bytes where a live host source has changed. RK01 reports, source and defect evidence remain unchanged.
