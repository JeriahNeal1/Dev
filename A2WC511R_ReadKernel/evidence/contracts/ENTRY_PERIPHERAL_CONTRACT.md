# Independent entry and peripheral contract

This contract is for the separate project-owned temporary RAM acquisition tool. It does not approve a vehicle connection or modify the frozen DUAL1.07 findings. The machine-readable details, register widths/masks and source-page index are in `ENTRY_PERIPHERAL_CONTRACT.json`.

The communication peripheral at `FFFFF010..FFFFF016` is **SCI2**, not SCI1. The proposed polling setup is SCR0, SMR0, SDCRF2, BRR9, a delay of at least one bit interval, then SCR30. At peripheral clock20MHz that is 62,500baud and the minimum interval is16us. PCCR word `FFFFF73C` selects PC2/TxD2 and PC3/RxD2 with bits0050; `(old&0155)|0050` retains other documented pin functions. This follows the [SH7058 Rev3 manual](https://www.renesas.com/en/document/mah/sh-2e-sh7058-f-ztat-tm-hardware-manual), sections15 and21.3.7, and the addresses used by the exact stock boot and captured DUAL routines. Clock frequency and board wiring remain physical assumptions. A deterministic virtual SCI event schedule is explicitly not a silicon timing model.

Status flags must follow hardware transitions: read TDRE1, write TDR, clear TDRE; the shift engine then sets TDRE and ultimately TEND. Receiving requires reading RDR and clearing a previously observed RDRF. ORER/FER/PER are not valid received data. TEND is read-only. Attempt03 bounds TX-ready and final TEND polling to65536 iterations, treats a timeout as an incomplete reply, and drains TEND before normal completion. RX idle and partial-frame waits deliberately remain read-only polling without a kernel deadline; host timeout and independently verified physical power loss terminate that stalled session. No whole-session wall-clock bound is claimed. DUAL's short setup does not contain a separately established one-bit settling delay; reproducing that omission is unnecessary.

The early keyed word `A518` to WDT address `FFFFEC10` disables its counter while writing documented reserved bits. This eliminates the inherited on-chip timer mode/period as a sustained-session dependency after that store. It does **not** identify an external watchdog: DUAL routine `FFFF3F50` toggles PBDR bit15 at `FFFFF738` after an interval event, and the inspected evidence does not prove that pin's board purpose. The new read tool must not silently copy that GPIO behavior. It may terminate if the board independently resets or removes power; it cannot claim a long session physically viable before that behavior is established.

A read followed by word0 to DMAOR `FFFFECB0` disables all four DMA channels; readback checks DME0. The master-disable policy avoids arbitrary inherited source/destination/count registers. This is a prospective stop, not evidence that no write occurred before the instruction, or that an upload already corrupted by DMA is intact. No DMA re-enable or generic channel reconfiguration is needed. The corresponding manual sections are10.2.5 and10.4.

The kernel should establish SR.I15, a private aligned SP and a fully initialized private VBR before accepting any request. NMI is priority16 and remains unmaskable. An exception pushes PC/SR, eight bytes; a private handler can select its own SP and enter quiet halt, but no software construction proves safety against arbitrary repeated NMI arrivals before the handler's first instruction. The entry transition before SP/VBR establishment is a precise asynchronous-event assumption, not hidden in a simulator default. A fully populated private vector table also prevents an unexpected exception from returning to an OEM handler after RAM takeover.

ROM reads require a stable user-MAT view. Read RAMER `FFFFEC26` as a word and reject RAMS mask8; read FMATS `FFFFE805` as a byte and reject nonzero for a conservative reset-state contract. The hardware actually selects user MAT for any value other thanAA, so accepting only0 is intentionally stricter. Neither guard writes those registers. Flash registers `FFFFE800..FFFFE806`, including prohibited `FFFFE803`, must never be store destinations; E803 must not be accessed at all. The firmware needs no FKEY, SCO, erase/program download, GPIO/FWE change or executable call outside the new object.

# Exact stock loader boundary

The stock input is SHA256 `22d52a5b3de7d86562eed2f85cca772db10e0949fcedc2d61b7540b45f760218`. The relevant code is in the already preserved `kernel_candidate/handoff_scope/OEM_1008_1F44.asm`.

| Operation | Actual stock instructions and project restriction |
| --- | --- |
| Declaration34 | `1890..193A` reconstructs address as FF000000+BE24, checks start at leastFFFF3000, calculated inclusive end at mostFFFF4FFF, start aligned4 and mode04. The project must independently require fixedFFFF3000, positive multiple-of4 length<=8192, preventing wrap/underflow and unsupported declarations. |
| Declaration ACK | `1828..183C` generates payload7484. It resets transfer bookkeeping; the previously captured installed host intentionally sent two identical declarations before any data. A new host need not infer that a second declaration is protocol-required. |
| Transfer36 | `1504..1660` constructs address, verifies declared range and aligned start, accumulates exactly four encrypted bytes, calls decrypt1E3C at163C, stores one plaintext longword at1646 and advances address4. ACK at183E is76. Preserve all ordered ciphertext and independently reconstruct complete plaintext. |
| Decrypt | Table32bytes at1C34; encryption keys7856,CE22,F513,6E86 at1C54..1C5B. Decrypt1E3C loads them in reverse, calls1F1A/1E94 for four rounds and swaps final halves. The fixed-round loop has no ciphertext-dependent branch. |
| Entry31 | `194C..19DA` requires01,01 then sums BE32 words of the declared upload, takes low16 and compares5AA5. A pad/correction longword can close the sum without changing executable bytes; ensure it is outside code and included in declaration. |
| Start ACK and jump | `1850..1868` forms710101. After successful ACK, `1992..19A0 -> 1C28` selectsFFFF3004 and SPFFFFBFA0. The new entry must set its own SP. |

The new `verify_oem_contracts.py` executed the exact stock decrypt routine on64 deterministic ciphertext vectors:403 instructions per word,48-byte stack, R8..R15/PR/MACH/MACL preserved and no non-stack store. A local additional MOV.W displacement decode was needed by this OEM routine;32 signed-data/displacement/delay-slot controls validate it. Existing tested shift extensions were reused read-only. `OEM_LOADER_REGRESSION.json` pins every imported file and trace hash. These are instruction tests of the actual stock decrypt routine, **not** an executed full OEM serial/security/session implementation. No earlier core or report was edited.

The positive ACK's transmitter at `1D00` polls TDRE and finally TEND at `1D76..1D7C`, but its timer branch can also return at `1D80`; the subsequent handoff does not inspect a success result. Therefore a successful normal ACK is useful host evidence, not an unconditional guarantee that every possible stock return drained the line. The packet checksum and low16 upload sum detect some corruption; neither authenticates all payload bytes or excludes checksum collisions. Executable/store closure remains conditional on the pinned upload actually residing intact and no asynchronous corruption. Host payload pins and two consistent ROM reads cannot independently prove that physical entry assumption.

The full BF producer is independently pinned by the existing `reports/local/prehardware/acquisition/BF_RESPONSE_CONTRACT.json`:62-byte frame, FF+56payload, ECU ID2F12515306 at response offsets[8,13). The alternate KWP dispatcher has now been recovered and its actual validators, sixteen-round seed producer and wire serializer executed; see `OEM_ACQUISITION_CONTRACT.md` and its hash-bound JSON. This supersedes the earlier producer uncertainty for the pinned stock and fixed request sequence. Physical acceptance and current-ROM equivalence remain separate assumptions.

# Exit and power boundary

This is RAM takeover in a stopped programming session, not a background diagnostic or OEM-preserving RAM allocation. Successful reads do not authorize jumping back into clobbered OEM state. Disconnect/Close only release the adapter. No inspected local vehicle wiring/service document establishes that ignitionOFF alone necessarily removes all ECU supply or RAM power. The stock boot code touches multiple GPIOs and DUAL periodically toggles PBDR15; neither is a qualified board relay/power-hold contract.

The future human exit criterion must therefore be **verified removal of ECU operating power sufficient to force reset**, followed by restored power, normal OEM initialization and passive identity confirmation. An arbitrary10-second key-off delay is not proof. The exact electrical observation/approved vehicle-specific disconnection method and required interval remain PHYSICAL_REQUIRED until supported by the correct wiring/service evidence. No engine/output/relay write is introduced to force shutdown. A fake process exiting or RAM model being cleared cannot satisfy this gate.

The smallest assumptions left after successful final-binary review are the correct actual boot-loader/current-ROM identity, stable powered clock/RAM, a clean entry window before private takeover, real UART/adapter timing and external watchdog/power/reset behavior. None depends on inherited `FFFF5444`, generic FF ROM residency or the MerpMod periodic writer.
