# A2WC Diaphora tools

The supported installation is `C:\Dev\Tools\diaphora-3.4.2-a2wc`. Its complete
source tree stays together. Project-local dependencies are in
`vendor\py314-win_amd64`; original `C:\Program Files\diaphora-3.4.2` remains
unchanged. HCLI is neither installed nor required by this workflow.

Run the complete acceptance test from any working directory:

```powershell
py -3.14 C:\Dev\Astra_A2WC511R\tools\diaphora\smoke.py
```

Every run creates a unique disposable directory beneath
`work\diaphora\smoke runs` and prints its `SMOKE_RESULT.json` path. The test:

- Creates two independent, identically configured IDBs from a 48-byte synthetic
  SH input, with three known leaf functions.
- Exports both through actual native IDA and the strict structural exporter.
- Checks a self-diff, independently repeated analysis and a clean-process repeat:
  three best instruction-identical matches, zero partial/ambiguous/unmatched.
- Rejects wrong-format and empty exports.
- Opens the real native Diaphora result chooser on a copied IDB, and verifies
  asymmetric unmatched primary/secondary roles with a labeled synthetic fixture.
- Records ROM/input, IDB, export, result and script hashes, native version, exact
  options, paths and process logs.

The final durable test, `durable_smoke_03_final`, passed when launched from
`C:\Program Files\diaphora-3.4.2`. All child tasks ran from an unrelated directory
whose path contains spaces; input/output filenames also contain spaces. No
global PYTHONPATH, installed plugin files or authoritative IDB was changed.

The measured installed native profile is IDA kernel **9.4**, native PE version
**9.4.260610.6c3b13fe**, IDAPython **9.4.0**, and CPython **3.14.7 AMD64** with
`.cp314-win_amd64.pyd` extensions. The kernel, IDAPython and Python observations
were measured inside native IDA, not inferred from the standalone runtime; the
PE build comes from the installed `ida.exe` version resource. The export JSON repeats the native Python
and IDAPython observations. An older IDB's producer version is a separate fact.
After replacing/upgrading a runtime, rerun `ida_environment_probe.py` through
native IDA and revise the ABI-specific dependency directory before proceeding.

`native_job.py` launches licensed native IDA with explicit absolute arguments,
hidden windows, and a process-local `IDAUSR` under `work\diaphora\ida_user_isolated`.
Two scoped PLUGIN_SKIP shadows prevent pre-existing duplicate Diaphora entries
from contaminating this process. Installed plugin trees remain untouched.
`export_native.py` then puts the real writable source and vendor directory first,
removes a previously cached shadow configuration module if necessary, and uses
typed settings rather than Diaphora's ambiguous environment-string booleans.

The structural profile includes autogenerated and library functions, assembly
and CFG data. It explicitly disables decompiler, microcode and trained-model
loading; SH-2E analysis does not require an unavailable SH decompiler. Export
exceptions propagate through an explicit crash hook, and export acceptance
checks every expected function address plus SQLite integrity and data counts.

For arbitrary closed exports, see [COMPARE_EXPORTS.md](COMPARE_EXPORTS.md).
That standalone comparison tool opens only disposable export copies and never
imports names, comments, types or boundaries. Its scores propose correspondence;
they do not prove ABI equivalence, literal-pool identity or executable-tail
ownership.

The raw-ROM comparison profile omits the 'Related compilation unit' pass through
a documented project hook: these exports have no genuine source/DWARF CU data,
and the inferred-CU pass repeats a potentially enormous Cartesian comparison.
That omission may leave additional homologs unmatched; it is not identity or
ownership evidence. Each comparison records the exact omission.

The optional numerical/ML packages load successfully, but the bundled sklearn
1.3.2 trained model is incompatible with installed sklearn 1.9.1. Model loading
stays disabled. The small source patches make three name-based identity shortcuts
honor existing ignore-name options and correct reversed unmatched-side labels.
Pre-fix negative tests, commits and complete diffs are retained under
`reports\local\diaphora\setup`.

names in the unmatched-reporting cache. The reporting method now takes the

and five affected family comparisons pass; a clean repeat gives the same
canonical result. The comparison driver requires matched and unmatched rows to
partition both complete function inventories. The combined current diff and
commit are in `setup\matcher_partition_repair`. Existing installation, exports
and stock self-comparison were reused during that continuation.
